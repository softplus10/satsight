# Internationalization

The URL selects the interface language through `?lang=<code>`:

| Code    | Language                             | Example        |
| ------- | ------------------------------------ | -------------- |
| `en_US` | English (United States), the default | `/?lang=en_US` |
| `en_CA` | English (Canada)                     | `/?lang=en_CA` |
| `ko_KR` | Korean (South Korea)                 | `/?lang=ko_KR` |

A missing, empty, or unsupported code falls back to `en_US`. Codes are matched case-insensitively; hyphens are also accepted, but generated links use the `language_REGION` form. Browser language and previously visited URLs do not override the current URL. No language preference is saved in local storage.

Internal links and programmatic navigation preserve `lang`. Query-only navigation and browser history update the active language. Use `localizedHref()` for every internal link or `goto()` destination; it preserves existing query parameters and fragments and does not modify external URLs.

## Catalogs and messages

Language files live together in `src/lib/i18n/locales/`:

```text
locales/
  en_US.ts  # Source catalog and English fallback
  en_CA.ts  # Shared English copy plus future Canadian wording overrides
  ko_KR.ts  # Complete Korean translation
```

`en_US.ts` defines the source messages and the `MessageKey` type. Use the shared helper in components and application errors:

```ts
import { t, localizedHref } from '$lib/i18n';

t('add_wallet');
t('remove_wallet_confirm', { name: wallet.name });
t('wallet_count', { count: 1 });
localizedHref('/wallets'); // /wallets?lang=ko_KR when Korean is active
```

Keys and required interpolation parameters are checked by TypeScript. Keep complete sentences and count phrases in the catalog rather than joining translated fragments. Render translations through normal Svelte text expressions; do not use `{@html}`.

Plural messages use `Intl.PluralRules`. Each must provide `other`; add `zero`, `one`, `two`, `few`, or `many` where the language requires them. Missing translations fall back to US English text and plural rules. Catalog tests check completeness and interpolation parameters for every bundled locale.

Application locale codes use underscores. Before calling `Intl` or setting the document's `lang`, the code converts them to BCP 47 tags: `en_US` → `en-US`, `en_CA` → `en-CA`, and `ko_KR` → `ko-KR`. This preserves regional number and date formatting without passing invalid underscore tags to browser APIs.

Protocol identifiers, network values in stored records, addresses, BTC/sats units, currency codes, and the SatSight name are not translated. Selecting a language does not change the wallet network or currency preferences.

## Add a language

1. Create a file such as `src/lib/i18n/locales/fr_CA.ts` with the same keys and placeholders as `en_US.ts`. Use `satisfies Required<TranslationCatalog>` to require a complete catalog and reject unknown keys.
2. Import and register it in `src/lib/i18n/catalogs.ts` under its `language_REGION` code.
3. Open `/?lang=fr_CA` to select it.
4. Run `npm run check` and `npm test`.

`t()`, `formatNumber()`, and `formatDate()` read Svelte locale state, so expressions update when the URL changes. Use `$derived` for translated arrays or computed labels in components; avoid translating once at module initialization. The root layout synchronizes locale state from `page.url` and updates the document's `lang` attribute. `setLocale()` is a low-level runtime helper; browser language selection should come from the URL.

## Stored data and native metadata

Generated address labels are translated at render time. New records store an empty default label. `addressLabel()` also recognizes older generated English/Korean labels without rewriting records. Custom labels, wallet names, and transaction notes remain user data and are never translated.

Application errors and in-progress operations use the language active when they occur. Previously saved error messages are not rewritten by a locale change.

Static HTML, the web manifest, and iOS camera permission text use English fallback copy. Additional native permission translations need the platform's localized resource files; adding a web catalog alone does not localize operating-system dialogs.
